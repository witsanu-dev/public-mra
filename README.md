> 
> * **การให้บริการเพื่อสาธารณประโยชน์ (Public Service Provision):**  
>   ระบบซอฟต์แวร์นี้จัดทำขึ้นเพื่อสนับสนุนการยกระดับคุณภาพบริการทางการแพทย์ของหน่วยบริการสุขภาพ โดยอนุญาตให้นำไปใช้งานได้โดยไม่มีค่าสิทธิการใช้งาน (Royalty-Free)
> 
> * **การติดตั้งและการบริหารจัดการแบบพึ่งพาตนเอง (Autonomous Self-Hosted Deployment):**  
>   หน่วยบริการผู้ใช้งานเป็นผู้รับผิดชอบในการจัดสรรทรัพยากร จัดเตรียมระบบคอมพิวเตอร์แม่ข่าย และดำเนินการติดตั้งตามระเบียบวิธีปฏิบัติทางเทคนิคด้วยตนเองอย่างสมบูรณ์
> 
> * **ขอบเขตการสนับสนุนทางเทคนิค (Technical Support Scope):**  
>   เนื่องจากผู้พัฒนามีพันธกิจและภาระงานประจำตามหน้าที่ จึงไม่มีนโยบายการให้บริการสนับสนุน ให้คำปรึกษาทางเทคนิครายหน่วยบริการ หรือฝึกอบรมการติดตั้งเป็นการส่วนตัว การประยุกต์ใช้งานให้ถือปฏิบัติตามคู่มือทางเทคนิคที่ระบุไว้ในคลังข้อมูลนี้เป็นสำคัญ
> 
> * **การคงไว้ซึ่งข้อมูลแสดงสิทธิของผู้สร้างสรรค์ (Preservation of Author Attribution):**  
>   การนำระบบไปใช้งานต้องคงไว้ซึ่งข้อความแสดงสิทธิ ข้อมูลอ้างอิง และเครดิตของผู้พัฒนาต้นฉบับ (**นายวิษณุ ศรีโยธา / wITsaNU _<**) อย่างครบถ้วนสมบูรณ์ในทุกส่วนแสดงผลและรหัสโปรแกรม ห้ามแก้ไข ปิดบัง หรือลบออกโดยเด็ดขาดตามพระราชบัญญัติลิขสิทธิ์

## 📋 บทสรุปภาพรวมระบบ (Overview)

**ระบบประเมินคุณภาพการบันทึกเวชระเบียนอิเล็กทรอนิกส์ (e-MR Audit: Electronic Medical Record Audit)** ได้รับการพัฒนาขึ้นเพื่อสนับสนุนกระบวนการตรวจประเมินคุณภาพการบันทึกเวชระเบียนของหน่วยบริการสุขภาพ **ตามมาตรฐานคู่มือการตรวจประเมินคุณภาพการบันทึกเวชระเบียน (Medical Record Audit Guidelines) ของสำนักงานหลักประกันสุขภาพแห่งชาติ (สปสช.) ปี 2563 - เล่มสีชมพู**

ระบบช่วยเปลี่ยนผ่านกระบวนการตรวจประเมินเวชระเบียนจากแบบเอกสารกระดาษสู่ระบบดิจิทัลที่สะดวกรวดเร็ว แม่นยำ และปลอดภัย สามารถเชื่อมต่อดึงข้อมูลผู้รับบริการจากระบบสารสนเทศโรงพยาบาล (HIS / HOSxP) ได้แบบ Real-time และรองรับโหมดการทำงานแบบ Standalone ผ่านการนำเข้าไฟล์ CSV สำหรับหน่วยบริการที่ไม่ได้เชื่อมต่อเครือข่าย HIS โดยตรง พร้อมระบบรายงานสถิติ แดชบอร์ดสรุปผล และระบบบันทึกประวัติการใช้งาน (Audit Trail) ตามมาตรฐานความปลอดภัยสารสนเทศ

## 🧩 ความสามารถและฟังก์ชันหลักของระบบ (Features & Capabilities)

### 1. แดชบอร์ดสรุปภาพรวมสำหรับผู้บริหาร (`/dashboard`)
* แสดงผลคะแนนเฉลี่ยรวมเปรียบเทียบกับเกณฑ์มาตรฐาน สปสช. (ผ่านเกณฑ์ ≥ 80.00%) ผ่านเข็มวัด KPI Gauge แบบ Real-time
* จำแนกคะแนนคุณภาพเวชระเบียนตาม 5 ประเภทบริการ: ผู้ป่วยนอก (OPD), ผู้ป่วยใน (IPD), อุบัติเหตุ-ฉุกเฉิน (ER), คลินิกโรคเรื้อรัง (NCDs), และจิตเวช (Psychiatric)
* กราฟวิเคราะห์แนวโน้มคะแนนเฉลี่ยย้อนหลัง 12 เดือน และสรุป 5 จุดบกพร่องที่พบบ่อยที่สุด
* สามารถพิมพ์รายงานสรุปผลสำหรับผู้บริหารในรูปแบบไฟล์อิเล็กทรอนิกส์ได้

### 2. ระบบตรวจประเมินเวชระเบียนผู้ป่วยนอกและฉุกเฉิน (`/` และ `/opd-table`)
* รองรับเกณฑ์ประเมินมาตรฐานตามคู่มือ สปสช. ปี 2563 (เล่มสีชมพู) 5 หมวดหมู่ 33 ข้อเกณฑ์ (Patient's Profile, History, Physical Exam, Investigation & Diagnosis, Treatment & Management)
* คำนวณคะแนนอัตโนมัติ รองรับการตัดข้อที่ไม่เกี่ยวข้อง (NA) ออกจากตัวหารอย่างถูกต้องตามเกณฑ์มาตรฐาน
* รองรับทั้งโหมดแสดงรายละเอียดเกณฑ์แบบเต็ม (Criteria View) และโหมดตารางความหนาแน่นสูง (Table View) สำหรับคีย์ข้อมูลรวดเร็ว

### 3. ระบบตรวจประเมินเวชระเบียนผู้ป่วยใน (`/ipd`)
* ครอบคลุมการตรวจเวชระเบียนผู้ป่วยในที่จำหน่ายแล้ว (Discharge Summary & Inpatient Records) ตามมาตรฐานคู่มือ สปสช. ปี 2563 (เล่มสีชมพู)
* รองรับการประเมินแยกตาม 6 กลุ่มโรค: อายุรกรรม, ศัลยกรรม, กุมารเวชกรรม, สูติ-นรีเวชกรรม, จิตเวช และโรคทั่วไป
* ระบบตรวจประเมินคะแนนเต็ม 56 คะแนน (กรณีทั่วไป) และ 57 คะแนน (กรณีจิตเวช)

### 4. ระบบตรวจประเมินเวชระเบียนผู้ป่วยจิตเวช (`/psychiatric`)
* หน้ารวมศูนย์สำหรับการตรวจประเมินเวชระเบียนผู้ป่วยจิตเวชโดยเฉพาะ ทั้งกรณีผู้ป่วยนอกและผู้ป่วยใน

### 5. ระบบสุ่มตรวจเวชระเบียน (`/sampling` และ `/ipd/sampling`)
* รองรับการสุ่มตัวอย่างจากฐานข้อมูล HIS ตามช่วงวันที่ แผนก หอผู้ป่วย คลินิก และขนาดตัวอย่างที่ต้องการ
* รองรับการนำเข้าไฟล์ CSV หรือบันทึกเคสตรวจประเมินด้วยตนเองในโหมด Standalone
* ระบบบริหารจัดการชุดการสุ่ม (Audit Batch) ติดตามความคืบหน้าการตรวจ และสรุปผลทั้งชุด

### 6. ระบบรายงานและส่งออกข้อมูล (`/reports`)
* สรุปผลคะแนนเปรียบเทียบตามแพทย์ผู้ตรวจ แผนก หอผู้ป่วย คลินิก และช่วงเวลา
* ส่งออกรายงานในรูปแบบ Microsoft Excel (.xlsx) ที่จัดรูปแบบตารางทางการแพทย์พร้อมสูตรคำนวณอัตโนมัติ

### 7. คู่มือมาตรฐานดิจิทัลในตัวระบบ (`/manual`)
* บรรจุคู่มือการตรวจประเมินคุณภาพการบันทึกเวชระเบียน (Medical Record Audit Guidelines) ของ สปสช. ปี 2563 - เล่มสีชมพู ฉบับเต็มในระบบ พร้อมเครื่องมือเปิดอ่าน ค้นหา และขยายเอกสารเทียบเคียงเกณฑ์การให้คะแนนได้ทันที

### 8. ระบบความปลอดภัยและการจัดการ (`/settings` และ `/audit-logs`)
* รองรับการยืนยันตัวตน 2 ขั้นตอน (Two-Factor Authentication: 2FA หรือ MFA / TOTP)  ด้วย Google Authenticator
* ระบบกำหนดสิทธิ์การใช้งาน (Administrator, Auditor, Officer)
* บันทึกประวัติการใช้งานระบบ (Audit Trail) ครบถ้วนตามมาตรฐานความมั่นคงปลอดภัย
* เครื่องมือทดสอบการเชื่อมต่อฐานข้อมูลและสำรองฐานข้อมูลท้องถิ่นในตัว

## 📊 ตารางเปรียบเทียบ: การตรวจด้วยกระดาษ vs ระบบ e-MR Audit

| ประเด็นการเปรียบเทียบ | การตรวจด้วยกระดาษแบบดั้งเดิม (Paper-based) | ระบบตรวจประเมิน e-MR Audit (Digital System) |
| :--- | :--- | :--- |
| **ระยะเวลาในการสุ่มเวชระเบียน** | 30 - 60 นาที (ต้องค้นหาและดึงแฟ้มจากห้องบัตร) | **< 3 วินาที** (ระบบสุ่มตัวอย่างจาก HIS หรือ CSV อัตโนมัติ) |
| **ความผิดพลาดในการคำนวณคะแนน** | พบบ่อย (คำนวณด้วยมือ, ลืมตัดตัวหาร NA) | **0%** (ระบบคำนวณคะแนนและตัด NA ตามเกณฑ์มาตรฐานอัตโนมัติ) |
| **การรวมผลและออกรายงาน** | ใช้เวลาหลายวัน (ต้องกรอกลง Excel อีกทอด) | **แสดงผลทันทีแบบ Real-time** พร้อมกราฟและดาวน์โหลดไฟล์ Excel ได้ทันที |
| **ความมั่นคงปลอดภัยของข้อมูล** | เสี่ยงต่อการสูญหาย เอกสารชำรุด หรือเปิดอ่านโดยพลการ | **ความปลอดภัยระดับสูง** เข้ารหัสข้อมูล มี 2FA และบันทึก Audit Trail ทุกขั้นตอน |
| **การเข้าถึงคู่มือเกณฑ์การตัดสิน** | ต้องพกพาหนังสือคู่มือเล่มหนา | **มีคู่มือดิจิทัลเปิดอ่านเคียงข้างหน้าจอตรวจได้ทันที** |
| **ความยืดหยุ่นในการใช้งาน** | ต้องอยู่ที่ห้องเวชระเบียนเท่านั้น | **ทำงานได้ทั้งโหมดเชื่อมต่อ HIS และ Standalone ออฟไลน์** |

## 📜 ความสอดคล้องกับมาตรฐาน (Compliance)

* **มาตรฐานคู่มือการตรวจประเมินคุณภาพการบันทึกเวชระเบียน (Medical Record Audit Guidelines) พ.ศ. 2563 (เล่มสีชมพู):** สำนักงานหลักประกันสุขภาพแห่งชาติ (สปสช.)
* **รหัสโรคและการวินิจฉัย:** มาตรฐาน ICD-10 และ ICD-9-CM องค์การอนามัยโลก (WHO)
* **การคุ้มครองข้อมูลส่วนบุคคล:** สอดคล้องกับแนวทาง พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)
* **การรักษาความปลอดภัยของระบบ:** สอดคล้องกับมาตรฐานการบันทึก Audit Trail และมาตรการรักษาความปลอดภัยสารสนเทศภาครัฐ

## 🚀 ขั้นตอนการติดตั้งและการ Deploy (Deployment Guide)

> ℹ️ **รูปแบบการนำไปใช้งาน (Autonomous Deployment Model):**  
> การนำระบบไปประยุกต์ใช้งานใช้รูปแบบการติดตั้งและบริหารจัดการแบบพึ่งพาตนเอง (Self-Hosted Model) ผู้ดูแลระบบต้องศึกษาคู่มือและดำเนินการติดตั้งบนสภาพแวดล้อมของหน่วยงานด้วยตนเอง โดยผู้พัฒนาไม่มีบริการสนับสนุนทางเทคนิคเฉพาะบุคคลอันเนื่องมาจากภาระงานประจำ

### 1. ความต้องการของระบบ (Prerequisites)
* **Node.js:** เวอร์ชัน 20 LTS หรือ 22 LTS ขึ้นไป
* **MySQL Server:** เวอร์ชัน 8.0 ขึ้นไป หรือ MariaDB 10.5 ขึ้นไป
* **เครือข่าย:** สามารถเชื่อมต่อไปยังฐานข้อมูล HOSxP ผ่าน TCP Port 3306 (กรณีเชื่อมต่อ HIS)

### 2. การเตรียมฐานข้อมูล (Database Setup)
นำเข้าโครงสร้างฐานข้อมูลเริ่มต้นจากโฟลเดอร์ `database/`:
```bash
mysql -u root -p db_mra < database/db_mra_20261008.sql
```

### 3. ตั้งค่าสภาพแวดล้อม (Environment Configuration)
คัดลอกไฟล์ `.env.example` เป็น `.env.local`:
```bash
cp .env.example .env.local
```
กำหนดค่าการเชื่อมต่อในไฟล์ `.env.local`:
```env
# Hospital HIS Database (Strict Read-Only)
HIS_DB_HOST=your_his_host_ip
HIS_DB_PORT=3306
HIS_DB_DATABASE=your_his_database
HIS_DB_USER=your_his_user
HIS_DB_PASSWORD=your_his_password

# MRA Dedicated Database (Full Read / Write)
MRA_DB_HOST=127.0.0.1
MRA_DB_PORT=3306
MRA_DB_DATABASE=db_mra
MRA_DB_USER=your_mra_user
MRA_DB_PASSWORD=your_mra_password

# Emergency Setup Key for pre-login database configuration & setup
ADMIN_SETUP_KEY=your_secure_admin_setup_key

# Session Secret (กำหนดข้อความสุ่ม 64 ตัวอักษรเพื่อความปลอดภัยสูงสุด)
SESSION_SECRET=your_random_64_character_session_secret
```

### 4. ติดตั้ง Dependencies และ Build ระบบ
```bash
npm install
npm run build
```

### 5. เริ่มต้นการทำงาน (Start Production Server)
```bash
npm start
```
หรือรันเป็น Background Service ด้วย PM2:
```bash
pm2 start npm --name "mra-system" -- start
pm2 save
pm2 startup
```

## 👨‍💻 ผู้พัฒนาและหน่วยงานรับผิดชอบ (Developer & Maintainer)

ระบบ **e-MR Audit (Electronic Medical Record Audit)** ได้รับการออกแบบ วิจัย และพัฒนาขึ้นโดย:

* **ผู้พัฒนา (Developer):** นายวิษณุ ศรีโยธา (`wITsaNU _<`)
* **ตำแหน่ง (Position):** นักวิชาการคอมพิวเตอร์
